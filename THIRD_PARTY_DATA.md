# Third-Party Data and Metadata

## CCHS respondent data and bootstrap weights

This repository does not distribute CCHS respondent-level data, bootstrap
weights, or derived respondent-level datasets. Each organization must obtain and
use its files under its own authorization and applicable Statistics Canada or
provincial data-sharing terms.

The MIT license in this repository applies to project code. It does not grant
rights to CCHS microdata supplied separately by an analyst or organization.

## CCHS harmonization metadata

Files named `harmonization/CCHS_<year>.json`, `categories.json`, and
`crosswalk.json` contain variable descriptions, category labels, and mappings
extracted or derived from cycle-specific CCHS codebook documentation. They do
not contain respondent records, frequencies, or weights. Full provenance
(record counts, checksums, extraction/matching method, and known limitations)
is recorded in `harmonization/cchs_harmonization_provenance.json`.

Primary survey documentation is available from Statistics Canada:

- Canadian Community Health Survey (CCHS) - Annual Component, Statistics
  Canada Survey number 3226
- <https://www.statcan.gc.ca/en/survey/household/3226>
- <https://www23.statcan.gc.ca/imdb/p2SV.pl?Function=getSurvey&SDDS=3226>

### Per-cycle variable/category files

`harmonization/CCHS_2021.json`, `CCHS_2022.json`, `CCHS_2023.json`, and
`CCHS_2024.json` were each generated by `scripts/extract_codebook.py` from
that cycle's local `codebooks/CCHS_<year>_DataDictionary_Freqs.pdf`, parsing
variable names, concept descriptions, and answer-category tables directly out
of the Statistics Canada codebook text. The 2021-2023 files were committed on
2025-10-02; the 2024 file was added on 2026-04-15.

Required source acknowledgment:

> Adapted from Statistics Canada, Canadian Community Health Survey (CCHS),
> Annual Component, cycle-specific Data Dictionary and Frequencies
> documentation. This does not constitute an endorsement by Statistics Canada
> of this product.

### Crosswalk and harmonized categories

`harmonization/crosswalk.json` is derived, not sourced from Statistics Canada
directly: `scripts/build_crosswalk.py` matches each 2024 (reference cycle)
variable to the closest-matching variable description in each earlier cycle
using fuzzy string matching (`difflib`, cutoff 0.6). This is a heuristic
concordance, not an authoritative Statistics Canada mapping - unmatched or
ambiguous variables are recorded as `null` and should be verified manually
before analytic use.

`harmonization/categories.json` is built on top of `crosswalk.json` by
`scripts/harmonize_categories.py`, which normalizes category labels (e.g.
"Yes"/"No"/"Valid skip"/"Don't know"/"Male"/"Female") across cycles using
simple keyword rules. Labels that do not match a rule pass through unchanged.

### Known extraction limitations

PDF text extraction introduces ligature artifacts in some descriptions (e.g.
"file" rendered as "ﬁle"). These are cosmetic text artifacts from the source
PDF's font encoding and do not change any variable name, code, or category
mapping.

### Codebook licensing note

Unlike the Ontario geographic lookups (distributed under the Statistics
Canada Open Licence), the CCHS Data Dictionary/codebook is typically supplied
to the receiving organization under a Statistics Canada or provincial CCHS
data-sharing agreement. Maintainers must rely on the terms of the agreement
under which their organization obtained the codebook - not the Open Licence -
when redistributing metadata derived from it, and should confirm that each
derived file remains consistent with the source documentation and those
terms before redistribution.

## Geographic lookup metadata

The Ontario census-subdivision and municipality lookup files contain public
geographic names and codes used for interface labels and filtering. Maintainers
should record the exact upstream dataset, edition, retrieval date, and licence
whenever these lookup files are regenerated. These lookup files contain no CCHS
respondent records.

## Codebook PDFs

Codebook PDFs are local inputs used by the extraction scripts and are not
distributed. `codebooks/*.pdf` is Git-ignored. Analysts must obtain codebooks
from an authorized source and comply with the source terms.
